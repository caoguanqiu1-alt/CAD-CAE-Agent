## 和最开始相比，具体改变了什么

| 维度 | 最初：直接 API 最小绘图/建模 | 当前：CAD-CAE Agent 工作流 |
| --- | --- | --- |
| 任务入口 | 人明确指定建一个矩形拉伸，C# 程序执行固定步骤。 | AI 客户端解释目标、制定建模/工况步骤，并通过 MCP 发起工具调用；执行仍由真实 COM 和 Simulation 完成。 |
| CAD 控制层 | 直接调用 `SolidWorks.Interop.sldworks` / `swconst`。 | 保留 API/COM 控制，外层新增 Python MCP 工具与 SW2020 稳定入口；MCP 初始化不触发 COM，首次实际调用再连接。 |
| 几何复杂度 | 一张中心矩形草图、一次拉伸、一个长方体。 | 草图、拉伸/切除计划、实体几何回读，并在限定的两孔连杆场景中构建独立销轴；复杂图纸的自动完整重建仍未得到通用验证。 |
| 校验方式 | 检查特征树、实体数、顶点、尺寸、体积和保存状态。 | 在上述几何检查之外，增加活动文档身份、未保存修改、持久面引用、研究状态、结果文件、重开回读和异常工况检查。 |
| 仿真能力 | 无有限元求解。 | 对指定材料、受力面、XYZ 力向量、固定与导向约束、多网格静力计划进行实际求解；支持示例销轴圆柱面无穿透接触。 |
| 输出产物 | 本机 `.SLDPRT` 和成功日志。 | 本机 `.SLDPRT`、原生 `.CWR`、多网格结果与 URES(mm) 云图；仓库只公开脱敏数值和截图。 |
| 可用性边界 | 只证明最小建模链路和当时的运行环境。 | 证明指定 SW2020 SP5/Simulation 环境与示例工况可运行；不等于任意零件、任意工况或工程安全签核。 |

直接 COM 仍是最底层的 CAD 控制方式。宏/VBA 是另一种进入同一 API 的方式；MCP 负责给 AI 客户端提供标准工具接口。当前系统的“Agent”部分来自客户端的理解、规划、选择和复核，**不是 MCP 服务一启动就具备独立自主决策能力**。

## 当前已验证的仿真例子

单次 MCP 计划曾在不同面施加两组不共线三维力 `(600, 50, 25)` N 与 `(400, -50, -25)` N，完成 5/4/3 mm 网格求解，最大合位移分别为 0.138554、0.138939、0.139222 mm。三实体销轴接触算例以大销轴固定、小销轴 +X 1000 N、两处轴向限位和一处 Z 向导向运行；5/4/3 mm 的最大合位移为 0.0111578、0.0111879、0.0112147 mm。详见[原始数值摘录与回读说明](cae/verification.md)及 [URES 云图](cae/assets/pin-guided-ures.png)。

这些工况中的载荷、材料、无摩擦接触、零间隙和导向是假设。位移的相邻网格变化低于 1%，但峰值应力没有达到相同收敛标准；曾出现求解成功却因自由运动得到异常大位移的情形。因此当前结论是“工作流已跑通并能识别部分无效工况”，不是零件已经完成强度、疲劳或安全验证。

## 新版定位

V1 的核心问题是：**能否不用鼠标，靠 API 真正画出并保存一个可检查的 SOLIDWORKS 零件？**本机实测答案是可以。

V2 的核心问题是：**能否让 AI 经 MCP 调用同一类真实 API，完成受约束的 CAD 建模、静力求解、结果回读，并标出尚未验证的工程假设？**在已记录的 SW2020 示例范围内，答案是可以。下一步若要扩大为通用工程 Agent，需要对不同零件的装夹/受力面判断、材料与接触模型、局部应力/接触压力收敛，以及独立复核继续验证。
