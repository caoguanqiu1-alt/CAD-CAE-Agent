## 最小技术补齐路径（建议，尚未实现）

DGX Spark 上运行本地模型与 Agent/Skill，负责工况规划、工具调度和结果判断；Windows x64 工程工作站运行当前 MCP/COM 执行层及合法安装的 SOLIDWORKS Simulation。
通过受控的跨机通道提交结构化任务，返回求解状态、数值及产物。需要实际验证鉴权、串行任务、长求解超时恢复及文件传输，不能直接把现有 minimal/stdio 配置暴露到公网。

DGX Spark 使用 Arm CPU，见 [NVIDIA 硬件文档](https://docs.nvidia.com/dgx/dgx-spark/hardware.html)。当前桥接依赖 Windows x64/.NET Framework/COM，所以不能把克隆仓库等同于在 Spark 上运行整个求解系统。
上述两机方案是技术建议，**赛事是否允许外部 Windows 工程软件执行端，需组委会确认**。

建议准备 3 个可复现实例：正常工况、约束不足时识别并停止、网格检查不通过时拒绝给出强度定型结论。
记录本地模型、硬件、软件版本、完整工具日志、耗时和原生结果，明确上游开源贡献与自己的新增工作。
